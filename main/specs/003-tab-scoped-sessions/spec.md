# Feature Specification: 分頁專屬的組別身分

**Feature Branch**: `feat/003-tab-scoped-sessions`

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: 人工驗證時在同一個瀏覽器開兩個視窗，A 視窗以 teamA 加入、B 視窗以 teamB 加入；A 視窗送出答案後，B 視窗再也無法以 teamB 送出（系統把它當成已作答的組別）。需重構網站的 cookie／session 狀態，讓同一個瀏覽器的不同分頁可以各自代表不同組別，教師登入也不會被學生加入影響。

## Clarifications

### Session 2026-11-25

- Q: 要用哪種方式讓同一個瀏覽器的分頁各自代表不同組別？ → A: 「分頁專屬代號＋HttpOnly cookie」：加入後網址帶一個分頁專屬的代號，伺服器依代號讀取對應的 HttpOnly cookie；同一個瀏覽器可同時是 A 組、B 組與教師，重新整理不會掉組別，前端程式讀不到身分憑證。（未採用：把憑證存在分頁的 sessionStorage 並以標頭送出——前端程式可讀取憑證，且學生頁面須改為純前端渲染。）
- Q: 舊的共用 cookie 怎麼處理？ → A: 不再讀取；更新後教師需重新登入、學生需重新加入（課堂活動本來就只維持數小時）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同一個瀏覽器的分頁各自代表不同組別 (Priority: P1)

助教或教師在同一台電腦、同一個瀏覽器（含所有無痕視窗）開多個分頁，分別以不同組別加入同一場活動；每個分頁之後送出的答案、看到的回執與結果，都只屬於該分頁加入的組別。

**Why this priority**: 這是人工驗證時發現的缺陷：後加入的組別會覆蓋先加入的身分，導致 A 分頁的答案被記成 B 組、B 組再也無法作答，搶答順位與得獎組別全部錯誤。Demo 與助教測試都會在單一電腦模擬多組，屬於核心流程阻斷。

**Independent Test**: 在同一個瀏覽器開兩個分頁，依序以 A 組、B 組加入；A 分頁先送出、B 分頁後送出；確認兩組答案都被受理，教師端顯示 A 組第 1、B 組第 2，且每組的答案內容正確。

**Acceptance Scenarios**:

1. **Given** 同一個瀏覽器的分頁 1 已以 A 組加入，**When** 分頁 2 以 B 組加入，**Then** 分頁 1 仍代表 A 組，分頁 2 代表 B 組。
2. **Given** 分頁 1（A 組）與分頁 2（B 組）都已加入且題目開放中，**When** 分頁 1 送出答案後分頁 2 送出答案，**Then** 兩份答案都被受理，A 組順位 1、B 組順位 2，各自的答案內容不互相取代。
3. **Given** 分頁 1 以 A 組加入，**When** 使用者重新整理分頁 1，**Then** 分頁 1 仍以 A 組身分顯示題目與自己的作答狀態，不需重新加入。
4. **Given** 題目開放中，**When** 分頁 1（A 組）收到即時更新，**Then** 只看到 A 組自己的回執，不會看到 B 組的答案。

---

### User Story 2 - 教師與學生可在同一個瀏覽器同時使用 (Priority: P1)

教師在瀏覽器分頁登入並開啟控制台，再在同一個瀏覽器開新分頁以學生身分加入（例如示範或自我測試）；教師分頁維持教師身分，可繼續開題、結束與回填。

**Why this priority**: 目前教師與學生共用同一個身分狀態，教師一旦在同一個瀏覽器加入學生就會失去教師權限，Demo 錄影時必然發生。

**Independent Test**: 教師登入後，在同一個瀏覽器另一分頁以 A 組加入；回到教師分頁開啟題目並結束，確認操作成功且不需重新登入。

**Acceptance Scenarios**:

1. **Given** 教師已登入，**When** 同一個瀏覽器的另一分頁以學生身分加入活動，**Then** 教師分頁仍可執行教師操作（開題、結束、回填）。
2. **Given** 學生分頁已加入，**When** 該分頁嘗試呼叫教師專用功能，**Then** 系統拒絕（權限不足），不會因同一個瀏覽器有教師登入就允許。

---

### User Story 3 - 組別身分不可被複製或挪用 (Priority: P2)

分頁的組別身分只在加入該組的瀏覽器中有效：把學生分頁的網址貼到另一台電腦或另一個瀏覽器，不能取得該組身分；某一場活動的身分也不能用在另一場活動。

**Why this priority**: 網址會帶分頁代號，必須確保代號本身不是憑證，避免學生把網址分享出去就能冒用其他組作答；不影響正常流程，因此次於 P1。

**Independent Test**: 複製學生分頁網址，在另一個瀏覽器開啟，確認被導回加入頁；以 A 活動的學生身分存取 B 活動，確認被拒絕。

**Acceptance Scenarios**:

1. **Given** 學生分頁網址含分頁代號，**When** 在沒有對應憑證的瀏覽器開啟該網址，**Then** 系統導回加入頁，送出答案的請求被拒絕（未登入）。
2. **Given** 學生已加入活動 A，**When** 以該身分存取活動 B 的即時更新或送出答案，**Then** 系統拒絕（無法存取此活動）。
3. **Given** 請求帶有格式錯誤或不存在的分頁代號，**When** 系統處理該請求，**Then** 視為未登入，不會退回使用同一瀏覽器中的教師或其他組身分。

---

### Edge Cases

- 同一個分頁重新加入（例如換組別）：取得新的分頁代號，網址更新為新代號；舊代號的身分在有效期限內仍屬於原組別，但該分頁不再使用它。
- 同一個瀏覽器在有效期限內加入非常多次：系統只保留最近的 10 個學生身分，較舊的身分自動失效（該分頁需重新加入）；過期或無效的身分在下次加入時一併清除。
- 學生直接開啟沒有分頁代號的學生頁網址：導回加入頁。
- 開新分頁時複製了學生分頁的網址（同一個瀏覽器）：兩個分頁代表同一組，屬於同組多人協作的既有行為。
- 更新前已登入的教師或已加入的學生：舊身分不再被讀取，需重新登入或重新加入。
- 舊的學生頁網址 `/activity`：導向新的學生頁並保留分頁代號。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每次學生加入活動，系統 MUST 產生一個新的、無法猜測的分頁代號，並以該代號建立一份只屬於這次加入（活動＋組別）的身分。
- **FR-002**: 同一個瀏覽器中同時存在的多份學生身分與教師身分 MUST 互不覆蓋；新的加入 MUST NOT 改變其他分頁的身分。
- **FR-003**: 學生分頁的所有請求（頁面載入、即時更新、送出答案、查詢結果）MUST 以該分頁的分頁代號選擇身分；未帶分頁代號的請求 MUST 只能使用教師身分。
- **FR-004**: 分頁代號本身 MUST NOT 足以取得身分：身分憑證 MUST 保存在前端程式無法讀取的 cookie 中，只有同時具備分頁代號與對應憑證的請求才被接受。
- **FR-005**: 分頁代號格式不正確、找不到對應憑證或憑證與代號不符時，系統 MUST 視為未登入，MUST NOT 退回使用教師或其他組的身分。
- **FR-006**: 學生身分 MUST 只能用於加入的那一場活動；教師專用功能 MUST 拒絕學生身分。
- **FR-007**: 學生分頁重新整理後 MUST 保持原組別身分；沒有有效分頁代號的學生頁 MUST 導回加入頁。
- **FR-008**: 教師身分 MUST 使用與學生身分分開的憑證，學生加入或重新加入 MUST NOT 影響教師身分。
- **FR-009**: 同一個瀏覽器最多保留 10 份有效學生身分；加入時 MUST 清除已過期或無效的學生身分，超過上限時 MUST 先移除最早到期的身分。
- **FR-010**: 既有的 API 路徑、請求與回應格式 MUST 維持相容；加入活動的回應 MUST 新增分頁代號欄位。

### Key Entities *(include if feature involves data)*

- **分頁代號（Seat）**：每次加入產生的隨機代號，出現在學生頁網址並隨每個學生請求送出；只用來選擇身分，不是憑證。
- **學生身分憑證**：伺服器簽章的學生身分（活動、組別、分頁代號、到期時間），存放在以分頁代號命名、前端無法讀取的 cookie。
- **教師身分憑證**：伺服器簽章的教師身分，存放在獨立的、前端無法讀取的 cookie。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在同一個瀏覽器以 N 個分頁（N ≤ 10）加入 N 個不同組別，每個分頁送出的答案 100% 記錄在自己的組別下，沒有任何答案被記到其他組或被誤拒。
- **SC-002**: 教師在同一個瀏覽器以學生身分加入任意次數後，教師操作成功率維持 100%，不需重新登入。
- **SC-003**: 在沒有對應憑證的瀏覽器使用學生分頁網址，取得組別身分的成功次數為零。
- **SC-004**: 學生分頁重新整理後，100% 保持原組別且不需重新加入。

## Assumptions

- 沿用 001 規格的身分有效期限（8 小時）與簽章方式；不新增伺服器端身分儲存。
- 同一個分頁要代表的組別以網址中的分頁代號為準；把學生網址複製到同一個瀏覽器的新分頁，視為同組另一位成員。
- 課堂與 Demo 均在本機網址執行；正式部署時 cookie 依環境啟用 Secure（沿用既有設定）。
- 學生端只有活動頁會發出學生請求；教師端頁面與 API 的使用方式不變。
- 共用系統圖（`diagrams/class.puml`、`sequence.puml`、`component.puml`）於與 004 合併時再統一更新；本功能的設計以 `diagrams/003-*.puml` 為準。
