# Feature Specification: 多題同時開放搶答與教師題目控制介面

**Feature Branch**: `feat/004-multi-question-rounds`

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: 希望改善教師搶答這部分。教師目前只能一次開放一題搶答，而且介面很醜（下拉式選單），題目變長時容易超出框框或無法完整顯示。希望改善介面，並把功能改成可以選擇多題、同時開放搶答。

## Clarifications

### Session 2026-11-25

- Q: 同時開放好幾題時，學生端要怎麼呈現？ → A: 所有開放中的題目依題號由上往下列出，每題一張卡片，各自有作答欄位（題組為每個子題一欄）、送出按鈕與「已送達」提示；已結束的題目顯示該題結果；每題的搶答順位與得獎組別各自獨立。
- Q: 教師端的題目控制要改成哪種版面？ → A: 「題目卡片清單＋勾選」：單欄卡片清單，上方固定工具列顯示已選題數、「開放所選題目」與「結束全部開放中」；只有可開放的題目有勾選框；題目文字完整換行；開放中的題目卡片直接展開即時排名與「結束本題」；已結束的題目卡片顯示得獎組別與回填操作；不再使用下拉式選單。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 教師勾選多題同時開放搶答 (Priority: P1)

教師在題目清單中勾選一或多個尚未開放的題目，按一次「開放所選題目」就讓這些題目同時開始搶答；已有題目在搶答中時，教師仍可再勾選其他題目加開。每題各自結束：教師可以只結束某一題，也可以一次結束所有開放中的題目。

**Why this priority**: 使用者明確要求「多題選擇同時開放搶答」，是本功能的核心；沒有它，學生端與介面改善都沒有意義。

**Independent Test**: 匯入 4 題的學習單，勾選第 1、2 題並開放，確認兩題同時為搶答中；再加開第 3 題；結束第 1 題後確認第 2、3 題仍在搶答中；按「結束全部開放中」後確認第 2、3 題同時結束。

**Acceptance Scenarios**:

1. **Given** 活動有 4 題且都尚未開放，**When** 教師勾選第 1、2 題並按「開放所選題目」，**Then** 第 1、2 題同時變成搶答中，第 3、4 題維持未開放。
2. **Given** 第 1、2 題搶答中，**When** 教師再勾選第 3 題並開放，**Then** 第 3 題也開始搶答，第 1、2 題的作答與順位不受影響。
3. **Given** 教師勾選的題目中有一題在送出前已被開放或已結束（例如在另一個視窗操作過），**When** 教師按「開放所選題目」，**Then** 所選題目全部不開放，系統指出是哪一題、原因為何，其他題目狀態不變。
4. **Given** 第 1、2、3 題搶答中，**When** 教師結束第 1 題，**Then** 只有第 1 題結束並公布結果，第 2、3 題繼續搶答。
5. **Given** 第 2、3 題搶答中，**When** 教師按「結束全部開放中」，**Then** 第 2、3 題同時結束，各自以結束當下已受理的答案決定結果。
6. **Given** 所有題目都已結束，**When** 教師檢視題目清單，**Then** 活動顯示為已完成，所有題目都不能再勾選或開放。

### User Story 2 - 學生同時作答多個開放中的題目 (Priority: P1)

學生畫面依題號由上往下列出所有開放中的題目，每題一張卡片，各自填寫並送出；送出後該題卡片顯示「答案已送達」，其他題目仍可作答。某題結束後，該題卡片改為顯示結果。

**Why this priority**: 教師同時開放多題後，學生若無法同時看到並作答所有題目，多題開放就無法使用；與 US1 同為核心流程。

**Independent Test**: 教師同時開放第 1、2 題，A 組先回答第 2 題、再回答第 1 題，B 組只回答第 1 題；確認第 1 題順位為 A 組（若先送）／B 組依實際送出先後，第 2 題只有 A 組；結束第 1 題後，學生端第 1 題顯示結果、第 2 題仍可作答。

**Acceptance Scenarios**:

1. **Given** 第 1、2 題搶答中，**When** 學生開啟活動頁面，**Then** 畫面依題號列出第 1、2 題兩張卡片，每張都有自己的作答欄位與送出按鈕（題組為每個子題一欄）。
2. **Given** A 組已送出第 2 題，**When** A 組檢視畫面，**Then** 第 2 題顯示「答案已送達」，第 1 題仍可作答。
3. **Given** 第 1、2 題搶答中，**When** A、B 兩組分別送出不同題目的答案，**Then** 每題的搶答順位只依該題的受理先後排列，不受其他題影響。
4. **Given** 第 1 題已結束而第 2 題仍在搶答中，**When** 某組送出第 1 題答案（例如畫面尚未更新），**Then** 系統拒絕並提示該題已結束；同一組送出第 2 題的答案照常受理。
5. **Given** 某題搶答中，**When** 學生檢視該題，**Then** 只看得到自己組別在該題的送出狀態，看不到其他組別的答案或順位；該題結束後才顯示所有組別的答案與得獎組別。
6. **Given** 學生在多題搶答中重新整理頁面，**When** 頁面重新載入，**Then** 所有開放中題目、自己已送出的狀態與已結束題目的結果都正確恢復。

### User Story 3 - 清楚易讀的教師題目控制介面 (Priority: P2)

教師在單欄的題目卡片清單中看到每一題的題號、題型、完整題目敘述（題組列出子題）與目前狀態；不需要下拉式選單。開放中的題目卡片直接顯示各組即時送出狀態與答案，並有「結束本題」；已結束的題目卡片顯示得獎組別與答案，並可回填至學習單，回填失敗時可重新回填。

**Why this priority**: 使用者反映目前介面難用且長題目會超出框框；它影響使用體驗與 Demo 品質，但功能本身已由 US1 提供，因此次於 P1。

**Independent Test**: 匯入含 300 字以上長題目與題組的學習單，在桌面寬度與 360px 手機寬度下開啟教師控制台，確認所有題目文字完整換行可見、沒有水平捲動；開放、作答、結束、回填各步驟中，卡片狀態標示正確。

**Acceptance Scenarios**:

1. **Given** 匯入的題目敘述很長，**When** 教師開啟控制台，**Then** 每題敘述完整換行顯示在卡片內，不被截斷、不超出卡片，手機寬度下也不需水平捲動。
2. **Given** 題目為題組，**When** 教師檢視該題卡片，**Then** 卡片標示「題組 · N 小題」並列出每個子題的標記與敘述。
3. **Given** 題目作答格尚未確認，**When** 教師檢視清單，**Then** 該題標示「作答格未確認」且沒有勾選框。
4. **Given** 某題搶答中，**When** 各組陸續送出，**Then** 卡片即時顯示每組的順位、答案（題組逐子題）或「等待作答」，並顯示該題已開放的時間。
5. **Given** 某題已結束且有得獎組別，**When** 教師按「回填得獎答案」，**Then** 卡片狀態依序顯示回填處理中與已回填；若回填失敗，卡片顯示「回填失敗」與原因，並提供「重新回填」。
6. **Given** 教師已勾選數題，**When** 教師捲動長清單，**Then** 工具列固定在可視範圍，持續顯示已選題數與開放／結束按鈕。

### Edge Cases

- 勾選後、送出前，所選題目被其他視窗開放或結束：整批不開放，指出題號與原因。
- 作答格未確認或已結束的題目：不可勾選；即使直接送出開放請求也會被拒絕。
- 同一題重複出現在同一次開放請求中：拒絕該請求。
- 「結束全部開放中」時沒有任何開放中的題目：按鈕停用；若仍收到請求，提示目前沒有開放中的題目。
- 「結束全部開放中」與學生送出同時發生：每題結果以該題結束當下已受理的答案為準，結束後才到的答案一律拒絕。
- 結束某題時，其他開放中題目正在受理答案：其他題目不受影響。
- 已結束的題目不能再開放（沿用 001）。
- 所有題目都結束後活動完成，不能再開放任何題目。
- 教師或學生斷線重連、重新整理：恢復所有開放中與已結束題目的最新狀態。
- 回填失敗（例如學習單結構改變）：可在修正學習單後重新回填；回填成功或處理中時不能重複送出。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 教師 MUST 能在題目清單中勾選一或多個可開放的題目（作答格已確認、尚未開放、尚未結束），並以一次操作同時開放所有選取的題目。
- **FR-002**: 一次開放多題 MUST 為全有或全無：任一選取題目不可開放時，MUST NOT 開放任何題目，並 MUST 指出不可開放的題號與原因。
- **FR-003**: 已有題目搶答中時，教師 MUST 仍能開放其他尚未開放的題目；同時開放的題目數量不設上限。
- **FR-004**: 每題 MUST 有獨立的搶答順位與得獎組別；某題的送出、拒絕或結束 MUST NOT 改變其他題目的順位、結果或狀態。
- **FR-005**: 每組對每一題 MUST 只被受理一次（沿用 001）；同一組可分別回答不同的開放中題目。
- **FR-006**: 教師 MUST 能個別結束任一開放中的題目，也 MUST 能一次結束所有開放中的題目；一次結束 MUST 在同一時點完成，結束後才到的答案 MUST 被拒絕。
- **FR-007**: 某題結束後，該題的送出 MUST 被拒絕並提示該題已結束；其他開放中題目的送出 MUST 照常受理。
- **FR-008**: 學生端 MUST 依題號由上往下列出所有開放中的題目，每題有自己的作答欄位（題組為每個子題一欄）、送出按鈕與送達確認；已結束的題目 MUST 顯示該題結果。
- **FR-009**: 題目搶答中時，學生 MUST 只看到自己組別在該題的送出狀態；該題結束後才 MUST 顯示所有組別的答案與得獎組別（沿用 001，逐題適用）。
- **FR-010**: 教師題目控制介面 MUST 以卡片清單呈現所有題目，MUST NOT 使用下拉式選單選題；題目與子題敘述 MUST 完整換行顯示，在 360px 寬的畫面上 MUST NOT 超出卡片或造成水平捲動。
- **FR-011**: 每張題目卡片 MUST 顯示題號、題型（單題／題組 N 小題）與狀態（未開放、作答格未確認、搶答中＋已開放時間、已結束、回填處理中、已回填、回填失敗）。
- **FR-012**: 開放中的題目卡片 MUST 即時顯示各組的送出狀態、順位與答案（題組逐子題），並提供「結束本題」。
- **FR-013**: 已結束的題目卡片 MUST 顯示得獎組別與其答案及所有組別的結果，並提供回填；回填失敗時 MUST 能重新回填，回填處理中或已成功時 MUST NOT 重複送出。
- **FR-014**: 教師的工具列 MUST 在捲動清單時保持可見，並顯示已選題數、「開放所選題目」與「結束全部開放中」。
- **FR-015**: 教師與學生畫面在重新整理或重新連線後 MUST 恢復所有開放中與已結束題目的最新狀態。
- **FR-016**: 活動 MUST 在所有題目都結束後才標示為完成；完成後 MUST NOT 再開放任何題目。

### Key Entities *(include if feature involves data)*

- **題目**：題號、題型（單題／題組）、題目與子題敘述、作答格確認狀態；每題在一場活動中最多被開放一次。
- **搶答回合**：一題的一次開放；有自己的開放時間、結束時間、受理順位與得獎組別；同一活動可同時有多個開放中的回合。
- **開放中題目集合**：活動目前所有搶答中的題目與其回合，用來判斷可否開放、可否受理送出及要結束哪些題目。
- **送出**：某組對某回合的完整答案（題組為每個子題一個答案）與受理順位。
- **回填工作**：某個已結束回合的得獎答案寫回學習單的工作與其狀態；失敗後可重新排入。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 教師勾選題目後，只需一次操作即可同時開放所有選取的題目；開放 3 題的總操作數不超過 4 次點擊。
- **SC-002**: 同時開放 N 題時，每題的得獎組別 100% 等於該題最先被受理的完整答案，跨題錯置次數為零。
- **SC-003**: 一次開放的題目中只要有一題不可開放，實際被開放的題目數為零。
- **SC-004**: 在 360px 與 1280px 寬的畫面上，500 字的題目敘述 100% 完整可見，頁面不出現水平捲動。
- **SC-005**: 教師與學生重新整理頁面後，不需任何額外操作即可看到所有開放中題目、自己的送出狀態與已結束題目的結果。
- **SC-006**: 一場 4 題的活動可完成「同時開放 2 題 → 兩組分別作答 → 結束其中 1 題 → 加開其餘題目 → 一次結束全部 → 逐題回填」的完整流程。

## Assumptions

- 同時開放的題目數量不設上限（最多為所有尚未結束的題目）。
- 已結束的題目不能重新開放（沿用 001）；回填仍由教師逐題觸發（沿用 002）。
- 題目開放後的計時僅供顯示，不會自動結束題目。
- 與 OpenSpec 小組約定的單題開放操作方式維持可用；新的多題開放與一次結束為新增能力。
- 本功能上線前已在進行中的舊活動不需移轉；Demo 前以新匯入的活動進行。
- 同一瀏覽器多分頁代表不同組別的身分隔離由 003 處理，不在本功能範圍。
- 沿用 001／002 的帳戶授權、組別、題組、即時同步、回填與權限模型。
