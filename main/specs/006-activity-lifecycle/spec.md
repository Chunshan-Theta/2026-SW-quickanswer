# Feature Specification: 我的課堂活動清單與關閉房間

**Feature Branch**: `feat/006-activity-lifecycle`

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: 關於頁面操作流程與順暢度：萬一老師不小心跳出控制台，整個房間會不會崩潰？老師有沒有辦法快速點回去？以及應該開放一個讓老師關閉房間的選項。

## Background

**老師跳出控制台，房間會不會崩潰？不會。** 活動、題目、各組送出、排名與回填狀態全部保存在伺服器（預設保留 7 天），不依賴教師頁面是否開著：老師離開控制台後，開放中的題目維持開放，學生照常作答，重新進入控制台時會從伺服器取回最新狀態並重新連上即時更新。

**真正的缺口是「回不去」。** 目前進入教師控制台的唯一入口，是匯入完成後畫面上的「進入教師控制台」連結；系統沒有記錄「這位老師有哪些活動」，控制台上的「返回匯入」也只會離開。只要那個網址不見了（關掉分頁、按了返回、重新整理匯入頁），老師就沒有辦法回到進行中的房間。另外，系統也沒有「結束這場活動」的方法：房間只會在保留期限到期後消失，期間學生仍能用活動代碼加入。

## Clarifications

### Session 2026-11-25

- Q: 老師離開控制台後，要用哪些方式快速回來？ → A: 只做「我的課堂活動」清單：放在教師工作區（教師登入後的落地頁、左側導覽「教師工作區」連到的頁面），列出這位老師的活動（進行中／已關閉）、活動代碼、題數、開放中題數、建立時間（以及已保存的學習單名稱），點一下回到該活動的控制台；進行中的排在前面。不另外加導覽列常駐按鈕，也不加離開頁面提醒。控制台的「返回匯入」改成回到教師工作區。
- Q: 老師按「關閉房間」之後要怎麼處理？ → A: 「結束活動但保留結果」：一次結束所有開放中的題目；學生端立即顯示「活動已結束」與各題已公布結果；之後不能再加入、開題或作答；老師仍可查看結果並回填尚未回填的題目；資料保留到原本的保留期限。關閉前在頁面內再確認一次。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師從「我的課堂活動」回到進行中的房間 (Priority: P1)

老師不小心離開控制台（按了返回、關掉分頁、跑去匯入另一份學習單）後，回到教師工作區就能看到自己的活動清單：每個活動顯示狀態、活動代碼、題數、開放中題數與建立時間，點一下即回到該活動的控制台，所有題目、即時排名與回填狀態都和離開前一致。

**Why this priority**: 使用者直接問「老師有沒有辦法快速點回去」。房間本身不會壞，但沒有入口就等於中斷上課；這是本功能最核心的價值。

**Independent Test**: 匯入學習單並開放第 1 題，讓一組送出答案；關閉控制台分頁，從左側導覽回到教師工作區，在「我的課堂活動」點選該活動，確認第 1 題仍在搶答中、該組的送出仍在排名上，學生端未受影響。

**Acceptance Scenarios**:

1. **Given** 老師匯入過兩份學習單，**When** 老師開啟教師工作區，**Then** 「我的課堂活動」列出這兩個活動，每個顯示狀態、活動代碼、題數、開放中題數、建立時間，以及學習單名稱（若有）。
2. **Given** 第 1 題搶答中且老師已離開控制台，**When** 老師在清單中點選該活動，**Then** 進入該活動的控制台，第 1 題仍在搶答中，各組送出與排名完整保留，學生端作答不受影響。
3. **Given** 老師有一個進行中、一個已關閉的活動，**When** 老師檢視清單，**Then** 進行中的活動排在已關閉的前面；同狀態依建立時間由新到舊。
4. **Given** 另一位老師也建立了活動，**When** 老師檢視清單，**Then** 只看得到自己建立的活動。
5. **Given** 某活動已超過保留期限而被系統清除，**When** 老師檢視清單，**Then** 該活動不再出現，也不會出現失效的連結。
6. **Given** 老師在控制台，**When** 老師按「返回教師工作區」，**Then** 回到教師工作區並能從清單再進入任一活動。

---

### User Story 2 - 老師關閉房間 (Priority: P1)

課堂結束時，老師在控制台按「關閉房間」並在頁面內確認。系統一次結束所有開放中的題目（以結束當下已受理的答案決定結果），將活動標示為已關閉：學生端立即看到「活動已結束」與各題已公布的結果，之後不能再用活動代碼加入、老師也不能再開題、學生不能再作答。老師仍可在控制台查看結果，並回填尚未回填的題目。

**Why this priority**: 使用者明確要求「開放一個讓老師關閉房間的選項」；沒有它，活動代碼在保留期限內一直有效，課後仍有人能加入或看到「等待老師開題」。

**Independent Test**: 開放第 1、2 題並讓 A 組回答第 1 題；老師按「關閉房間」→ 確認；確認第 1、2 題同時結束、第 1 題得獎為 A 組；學生端顯示「活動已結束」；用活動代碼加入被拒絕；老師仍能回填第 1 題。

**Acceptance Scenarios**:

1. **Given** 第 1、2 題搶答中，**When** 老師按「關閉房間」，**Then** 頁面先顯示確認區塊，說明會結束幾題開放中的題目、學生將無法再加入或作答、結果與回填會保留；按「取消」則什麼都不變。
2. **Given** 確認區塊已顯示，**When** 老師按「確認關閉房間」，**Then** 所有開放中的題目在同一時點結束並公布結果，活動標示為「已關閉」。
3. **Given** 活動已關閉，**When** 學生端仍開著活動頁面，**Then** 學生不需重新整理即看到「活動已結束」與各題已公布的結果，沒有任何可作答的題目。
4. **Given** 活動已關閉，**When** 有人用活動代碼查詢或加入，**Then** 系統拒絕並說明活動已關閉。
5. **Given** 活動已關閉，**When** 老師或任何人嘗試開放題目、學生嘗試送出答案，**Then** 系統拒絕並說明活動已關閉（或該題已結束）。
6. **Given** 活動已關閉且第 1 題有得獎答案尚未回填，**When** 老師在控制台按回填，**Then** 回填照常進行並顯示結果。
7. **Given** 活動已關閉，**When** 老師（例如在另一個分頁）再次關閉，**Then** 系統直接回報活動已關閉，狀態與結果不再改變。
8. **Given** 活動已關閉，**When** 老師檢視「我的課堂活動」，**Then** 該活動顯示「已關閉」，仍可點進控制台查看結果。

---

### Edge Cases

- 關閉房間與學生送出同時發生：每題結果以結束當下已受理的答案為準，之後到的答案一律拒絕。
- 關閉房間時沒有任何開放中的題目（例如還沒開題或全部已結束）：照樣關閉，不需要結束任何題目。
- 關閉房間的同時，老師在另一個分頁開放了新題目：關閉後不能留下任何開放中的題目（新開的題目也一併結束，或開題請求被拒絕）。
- 其他老師或學生嘗試關閉房間：拒絕，活動不變。
- 老師在作答格尚未確認（待確認）的狀態下關閉：允許，活動直接變成已關閉。
- 已關閉的活動仍保留到原本的保留期限，期滿後從清單中消失。
- 學生在活動關閉後重新整理頁面：仍看到「活動已結束」與已公布結果，不會被要求重新加入。
- 老師的清單很長：只顯示最近的活動（上限 50 筆），進行中的排在前面。
- 本功能上線前建立的舊活動沒有登記在清單中：仍可用原本的控制台網址進入（保留期限內）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在老師每次成功匯入學習單建立活動時，記錄該活動屬於這位老師，保留期限與活動相同。
- **FR-002**: 教師工作區 MUST 顯示「我的課堂活動」清單，只列出目前登入老師建立且仍在保留期限內的活動；MUST NOT 列出其他老師的活動，學生與未登入者 MUST NOT 取得任何清單。
- **FR-003**: 清單中每個活動 MUST 顯示：狀態（進行中／已關閉）、活動代碼、題數、開放中題數、建立時間，以及已保存的學習單名稱（若有），並 MUST 提供進入該活動控制台的連結。
- **FR-004**: 清單 MUST 將進行中的活動排在已關閉的前面，同狀態依建立時間由新到舊排列，最多顯示最近 50 筆。
- **FR-005**: 已過保留期限而被清除的活動 MUST NOT 出現在清單中。
- **FR-006**: 教師控制台 MUST 提供回到教師工作區的連結（取代原本的「返回匯入」）；重新進入控制台時 MUST 顯示伺服器上的最新狀態（沿用 004 的快照與即時同步）。
- **FR-007**: 教師控制台 MUST 提供「關閉房間」操作，且 MUST 在頁面內先顯示確認區塊（說明將結束的開放中題數與關閉後的影響），老師確認後才執行；取消時 MUST NOT 改變任何狀態。
- **FR-008**: 關閉房間 MUST 在同一時點結束所有開放中的題目（每題以結束當下已受理的答案決定結果並公布），並將活動標示為已關閉；關閉後 MUST NOT 留下任何開放中的題目。
- **FR-009**: 只有建立該活動的老師 MUST 能關閉房間；其他老師、學生與未登入者的請求 MUST 被拒絕且活動不變。
- **FR-010**: 關閉已關閉的活動 MUST 直接回報已關閉的狀態，MUST NOT 再產生任何變更。
- **FR-011**: 活動關閉後，系統 MUST 拒絕以活動代碼查詢或加入、MUST 拒絕開放題目、MUST 拒絕學生送出答案，並以中文說明活動已關閉（或該題已結束）。
- **FR-012**: 活動關閉後，開著活動頁面的學生 MUST 不需重新整理即看到「活動已結束」與各題已公布的結果；重新整理後 MUST 仍看到相同畫面。
- **FR-013**: 活動關閉後，教師控制台 MUST 標示房間已關閉並停用開放／結束題目的操作，但 MUST 仍可查看所有題目的結果與回填尚未回填的題目。
- **FR-014**: 已關閉的活動 MUST 保留到原本的保留期限，期間仍出現在清單中並可進入控制台查看。

### Key Entities *(include if feature involves data)*

- **教師活動清單**：某位老師建立的活動與建立時間；與活動同樣在保留期限後失效。
- **活動**：新增「已關閉」狀態與關閉時間；已關閉是終止狀態，不能再加入、開題或作答。
- **活動摘要**：清單中一筆活動的顯示資料（狀態、活動代碼、題數、開放中題數、已結束題數、組數、建立時間、學習單名稱）。
- **活動已結束事件**：活動關閉時送給教師與所有學生的即時通知，讓畫面立即切換為已結束。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 老師離開控制台後，從教師工作區回到進行中的活動不超過 2 次點擊（導覽列「教師工作區」→ 清單中的活動）。
- **SC-002**: 老師離開控制台再回來後，題目狀態、各組送出與排名 100% 與離開前一致，學生端作答期間沒有任何中斷。
- **SC-003**: 清單中出現其他老師的活動次數為零；出現已過期活動的次數為零。
- **SC-004**: 關閉房間後，開放中題目數為零；學生端在 2 秒內看到「活動已結束」。
- **SC-005**: 關閉房間後，加入、開題與送出答案的成功次數為零；尚未回填的題目仍 100% 可回填。
- **SC-006**: 一場活動可完成「開放題目 → 離開控制台 → 從清單回來 → 關閉房間 → 回填剩餘題目」的完整流程。

## Assumptions

- 清單放在既有的教師工作區頁面（匯入頁），不新增頁面；左側導覽「教師工作區」已連到這裡。
- 學習單名稱取自老師在 Google Picker 選到的檔名與工作表分頁名稱，於匯入時一併保存；不額外呼叫 Google API。
- 「進行中」包含尚未開題、待確認作答格、搶答中與所有題目已結束但尚未關閉的活動；「已關閉」只指老師按過「關閉房間」的活動。
- 已關閉的活動不能重新開啟；要再上課請重新匯入建立新活動。
- 活動代碼在已關閉後仍保留到期限，不會分配給新活動，避免學生誤入別的房間。
- 本功能上線前建立的舊活動不回填登記；Demo 前以新匯入的活動進行。
- 不新增導覽列常駐「回到進行中的活動」按鈕，也不加離開頁面提醒（使用者未選擇）。
- 回填的選擇與學生端的答案公布方式由 005 處理，不在本功能範圍；本功能只保證關閉後仍可回填。
- 沿用 001～004 的帳戶授權、分頁身分、多題開放、即時同步、回填與權限模型。
