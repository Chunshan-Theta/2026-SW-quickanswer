# Feature Specification: 官方 Guided Notes 範本匯入與逐題回填

**Feature Branch**: `feat/002-guided-notes-template-import`

**Created**: 2026-11-23

**Status**: Draft

**Input**: User description: 人工驗證時發現系統無法匯入課程提供的官方 Guided Notes 範本（單題範本、題組+單題範本）：範本以表格呈現「題號｜題目｜作答」三欄且作答格為空白，系統卻只認得「題號與題目寫在同一格」及答案格內的特殊記號；教師必須手動輸入工作表內部識別碼，預設值又不符合複製後的範本；匯入失敗時沒有說明原因；且第一題回填後，後續題目的回填都會被誤判為工作表已變更而失敗。需讓系統直接辨識官方範本的表格格式、讓教師以名稱選擇工作表分頁、列出具體錯誤，並確保活動中每一題都能回填。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 直接匯入官方表格格式學習單 (Priority: P1)

教師從雲端硬碟選取依官方範本製作的學習單，從分頁清單中選擇要使用的工作表（只有一個分頁時自動選好），系統依表格的標題列辨識「題號」、「題目」、「作答」欄，逐題找出題號、題目敘述與作答格，教師不需在試算表中加入任何特殊記號。

**Why this priority**: 助教會以另一份同格式的 Guided Notes 測試；若無法匯入官方範本，後續搶答與回填全部無法進行，屬於核心功能阻斷。

**Independent Test**: 複製官方單題範本後直接匯入，確認題數、題號與題目敘述與工作表一致；在複本中插入欄、列或調換欄位順序後再匯入，確認仍正確辨識。

**Acceptance Scenarios**:

1. **Given** 教師選取一份依官方單題範本製作、作答格空白的學習單，**When** 教師選擇分頁並匯入，**Then** 系統列出與工作表相同數量的題目，每題顯示題號、題目敘述及「作答格已確認」。
2. **Given** 試算表只有一個分頁，**When** 教師選好試算表，**Then** 系統自動選取該分頁，教師不需輸入任何識別碼。
3. **Given** 試算表有多個分頁，**When** 教師選好試算表，**Then** 系統以分頁名稱列出所有分頁供教師選擇。
4. **Given** 學習單的欄或列被移動（例如在題號欄前插入一欄、在標題列上方插入數列），**When** 教師重新匯入，**Then** 系統依標題列與題號重新辨識，結果與移動前一致。
5. **Given** 學習單使用既有的記號格式（題號與題目同格、作答格內含答案記號），**When** 教師匯入，**Then** 系統仍可如以往成功匯入。

---

### User Story 2 - 活動中每一題都能回填 (Priority: P1)

教師在同一場活動中依序完成多題搶答，並在每題結束後（或稍後）將得獎答案回填至原學習單；先完成的回填不會讓後續題目的回填失敗。

**Why this priority**: 「匯出搶答成功的組別答案至原 Guided Notes」是核心功能；目前只有第一題能回填成功。

**Independent Test**: 匯入三題的學習單，完成三題搶答並逐題回填，確認三題得獎答案皆寫入各自的作答格，其餘儲存格不變。

**Acceptance Scenarios**:

1. **Given** 第 1 題已回填成功，**When** 教師回填第 2 題，**Then** 第 2 題答案寫入第 2 題的作答格，回填狀態為成功。
2. **Given** 教師在匯入後修改了學習單中與題目結構無關的內容（例如標題文字或格式），**When** 教師回填任一題，**Then** 回填照常成功。
3. **Given** 匯入後某題的題號、題目列或作答格被刪除或移到無法唯一確認的位置，**When** 教師回填該題，**Then** 系統不寫入任何儲存格，並說明該題結構已變更、需重新匯入。
4. **Given** 回填成功，**When** 教師檢視原學習單，**Then** 只有目標作答格的內容改變，其他儲存格（含其他題目的作答格）保持原樣。

---

### User Story 3 - 看得懂的匯入錯誤 (Priority: P2)

匯入失敗時，教師看到逐項列出的問題（例如「第 3 題找不到作答格」、「題號 2 重複」、「找不到含『題號』與『作答』的標題列」），知道要修改學習單的哪裡。

**Why this priority**: 教師無法自行排除問題時整個活動會卡住；但不影響格式正確時的主要流程，因此次於 P1。

**Independent Test**: 分別準備缺少作答欄、題號重複、題號不連續、空白分頁的學習單並匯入，確認每種情況都顯示對應且具體的問題說明。

**Acceptance Scenarios**:

1. **Given** 學習單有題號重複或缺漏，**When** 教師匯入，**Then** 系統列出出問題的題號，且不建立活動。
2. **Given** 選取的分頁中沒有可辨識的標題列也沒有記號格式題目，**When** 教師匯入，**Then** 系統說明找不到題目，並提示支援的學習單格式。
3. **Given** 某題的作答格無法辨識，**When** 教師匯入，**Then** 系統指出是哪一題、位於工作表第幾列。

---

### User Story 4 - 題組搶答 (Priority: P2)

官方「題組+單題範本」中，一個題號下可包含多個子題，每個子題各有一個作答格（作答格內可能有「（1）」「（2）」等子題標記）。教師匯入後，題組與單題一樣以題號為單位逐題開放；學生必須在同一次送出中填完該題組所有子題的答案；最快送出完整答案的組別為該題組的搶答成功組別；回填時每個子題答案寫入各自的作答格。

**Why this priority**: 題組是專題的額外功能（「搶答時須同時送出的題目」），且助教可能以題組範本測試；單題流程不依賴本故事。

**Independent Test**: 匯入官方題組+單題範本，確認題數以題號計（題組算一題）；開放題組題目，兩組各送出完整子題答案，確認最先送出的組別勝出；回填後確認每個子題作答格都寫入對應答案。

**Acceptance Scenarios**:

1. **Given** 學習單中某題號跨越多列且有多個作答格，**When** 教師匯入，**Then** 系統將其辨識為一個題組（題數以題號計），預覽中列出各子題敘述與作答格，而非多個重複題號的單題或錯誤。
2. **Given** 教師開放一個有 2 個子題的題組，**When** 學生檢視題目，**Then** 學生看到 2 個子題的敘述與各自的作答欄位。
3. **Given** 題組題目開放中，**When** 學生只填寫部分子題就送出，**Then** 系統拒絕送出並提示所有子題都必須作答，且不占用搶答順位。
4. **Given** 兩組先後送出完整的題組答案，**When** 教師結束該題，**Then** 先送出的組別為搶答成功組別，結果中顯示各組每個子題的答案。
5. **Given** 題組題目已結束且有得獎組別，**When** 教師回填，**Then** 得獎組別每個子題的答案寫入該子題的作答格；作答格原有的子題標記（如「（1）」）保留在答案前方。

---

### Edge Cases

- 標題列上方有學習單標題、空白列或說明文字：系統忽略標題列以上的內容。
- 題目或作答格為跨欄合併儲存格：視為單一格，回填寫入合併範圍。
- 題目之間以空白列分隔：空白列不視為題目或錯誤。
- 作答格在匯入時已有內容：匯入可進行並於預覽中提示；回填時以得獎答案取代該格內容。
- 同一分頁同時出現表格標題列與記號格式：以表格格式為準。
- 試算表沒有任何分頁可讀取或教師失去權限：顯示權限或內容錯誤，不建立活動。
- 回填期間教師同時編輯同一作答格：沿用既有假設，最後掃描與寫入之間不保證原子性。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 教師選取試算表後，系統 MUST 以分頁名稱列出可用的工作表分頁供選擇；只有一個分頁時 MUST 自動選取；教師 MUST NOT 需要輸入分頁的內部識別碼。
- **FR-002**: 系統 MUST 辨識表格格式學習單：找出同時含有「題號」欄名及「作答」或「答案」欄名的標題列，並以該列決定題號欄、題目欄與作答欄。
- **FR-003**: 系統 MUST 依標題列與各列題號內容動態辨識題目與作答格；欄、列位置改變後 MUST 仍能正確辨識，MUST NOT 使用固定儲存格座標。
- **FR-004**: 系統 MUST 將合併儲存格視為單一格處理（包含跨欄合併的題目、作答格及跨列合併的題號）。
- **FR-005**: 系統 MUST 繼續支援既有的記號格式；同一分頁中偵測到表格標題列時 MUST 以表格格式辨識。
- **FR-006**: 匯入的題數 MUST 等於標題列下方具有效題號的題目數；題號重複、缺漏、作答格缺失或無法唯一辨識時 MUST 阻止建立活動。
- **FR-007**: 匯入失敗時，系統 MUST 逐項列出問題，每項包含問題類型及可定位的資訊（題號或工作表列號）。
- **FR-008**: 教師 MUST 能將活動中任一已結束且有得獎組別之題目的答案回填至該題作答格；先前題目的回填 MUST NOT 導致後續題目回填失敗。
- **FR-009**: 回填前，系統 MUST 重新確認該題的題號、題目列與作答格位置與匯入時一致；不一致時 MUST NOT 寫入並 MUST 回報需重新匯入。作答格內容的變動（包含先前的回填）及與題目結構無關的變動 MUST NOT 被視為結構不一致。
- **FR-010**: 回填 MUST 只改變目標作答格的內容，其他儲存格 MUST 保持不變；寫入後系統 MUST 確認目標格內容等於得獎答案才回報成功。
- **FR-011**: 系統 MUST 辨識題組結構：同一個（合併或相鄰重複的）題號跨越多列、且各列有不同作答格時，視為一個題組；題號欄空白但緊接在題目下方、且有子題敘述或子題標記的列，視為該題的子題。題組以題號計為一題。
- **FR-012**: 題組題目開放時，學生端 MUST 顯示所有子題敘述與對應的作答欄位；學生 MUST 一次送出所有子題答案，任一子題空白時 MUST 拒絕送出且不分配搶答順位。
- **FR-013**: 題組的搶答順位與得獎判定 MUST 與單題相同（以完整答案被系統受理的先後為準）；結果 MUST 顯示各組每個子題的答案。
- **FR-014**: 題組回填 MUST 將得獎組別每個子題的答案寫入各自的作答格；作答格在匯入時若含子題標記（例如「（1）」），回填內容 MUST 保留該標記並接上答案。
- **FR-015**: 教師控制台 MUST 列出本場活動已結束的題目及其得獎組別與回填狀態，讓教師可對任一已結束的題目執行回填（支援 FR-008）。

### Key Entities *(include if feature involves data)*

- **工作表分頁**：試算表中的一個分頁，以名稱呈現給教師，系統內部以識別碼對應。
- **表格版面**：由標題列決定的欄位對應關係（題號欄、題目欄、作答欄）及標題列位置。
- **題目**：題號、題目敘述及其作答格（單題一格；題組為每個子題一格）。
- **題組**：同一題號下的多個子題，每個子題有自己的題目敘述與作答格。
- **結構快照**：匯入時記錄的各題題號、題目列與作答格位置，回填前用來比對結構是否仍一致；不包含作答格內容。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 依官方單題範本製作的學習單（包含欄、列移動後的版本），100% 可在不加任何記號的情況下匯入，且題數與題號與來源完全一致。
- **SC-002**: 教師從選取試算表到看到題目預覽，不需要輸入任何識別碼，且可在 1 分鐘內完成。
- **SC-003**: 一場有 N 題的活動中，N 題的得獎答案都能成功回填到各自的作答格，回填成功率不因題目先後而下降。
- **SC-004**: 每一次匯入失敗都至少顯示一項具體問題（含題號或列號）；不再出現沒有說明原因的失敗訊息。
- **SC-005**: 題目結構變更後的回填，寫入錯誤位置的次數為零。
- **SC-006**: 依官方題組+單題範本製作的學習單可直接匯入，題數等於題號數；題組題目可完成「開放 → 各組送出完整答案 → 結束 → 回填所有子題」的完整流程。

## Assumptions

- 標題列的欄名為「題號」、「題目」、「作答」或「答案」，比對時忽略前後空白；標題列以上的內容（學習單標題、空白列）不影響辨識。
- 題號為阿拉伯數字，自 1 開始連續編號；題目之間可以有空白列。
- 教師提供的學習單作答格原則上為空白；若已有內容，回填時以得獎答案取代。
- 一場活動只使用一個分頁；跨分頁合併匯入不在本功能範圍。
- 教師控制台的「已結束題目清單」僅提供得獎組別、各組答案與回填操作；學生端的跨題結果總覽不在本功能範圍，另立規格處理。
- 題組子題標記的格式為全形或半形括號包住的數字（例如「（1）」、「(2)」）；沒有標記的子題回填時直接寫入答案。
- 記號格式（題號與題目同格＋答案記號）僅支援單題；題組須使用表格格式。
- 沿用 001 規格的 Google 帳戶授權、搶答流程、回填工作佇列與權限模型。
